我一直想做一个打开就能玩的泰拉瑞亚。不是商业项目，也不是像素级复刻，只是想验证一件事：浏览器里能不能跑起一个真的可以挖矿、建造、打 Boss 的世界。

现在它在这里：<https://stanl.top/terraria>

![白天的出生点](https://stanl.top/terraria-deepseek-v4.1-flash/screenshots/spawn-day.png)

## 做了什么

- 程序化生成的世界：森林、雪原、沙漠、丛林、海洋、腐化 / 猩红，以及洞穴、矿道、地牢和地狱
- 挖掘、放置、合成、箱子、床、工作台和几种制作站
- 近战、远程、魔法、召唤四条战斗路线
- 42 种敌人、7 个 Boss、6 位 NPC
- 昼夜、天气、入侵事件、掉落物和角色存档
- 一整套中文界面

游戏是纯静态的，没有后端，也没有任何外部图片素材。地形、树木、角色、敌人和图标都用 Canvas 画出来，存档放在浏览器的 `localStorage` 里。代码大部分是 AI 写的，我做得最多的事情是把它跑起来、玩一遍，然后告诉它哪里不对。

## 细节问题

功能表看起来很长，但让游戏从「能跑」变成「能玩」的是另一批问题。

第一次打开游戏，鼠标一进画面就消失了。原因是 CSS 里写了 `cursor: none`，而游戏自己画的准星又小得几乎看不见。最后的处理很简单：菜单里用默认指针，游戏中用 `crosshair`，准星交还给浏览器。

类似的问题还有很多：Boss 血条压住名字，任务追踪挡住聊天，背包里的属性行叠在一起，Tooltip 曾经算出过 `404% 暴击`，还有一个物品因为名字没翻译，直接让整个合成面板崩了。

为了不靠肉眼碰运气，我写了几组自动检查：42 种敌人是否都能生成和更新，105 条武器 / 工具 / 药水使用路径是否都能跑通，34 个饰品是否都能正确计算，7 个 Boss 的每个阶段是否都能完成。它们不能证明游戏好玩，但至少能保证改中文的时候没有把战斗改崩。

## 中文界面

这次翻译涉及 363 个物品名，以及所有 NPC 对话、任务、聊天、死亡提示和系统消息。

一开始我以为把英文替换成中文就结束了，后来发现根本不是。原来的像素字体 `Press Start 2P` 不包含汉字，所有中文都会退化成系统默认字体；中文字号又比英文大，原本按 6px 排的 HUD 一换中文就全挤在一起。

最后做了三件事：

- 给字体加上中文 fallback，并让工具函数识别 CJK 字符
- 把换行、行高、Tooltip 高度都按中文重新计算
- 把整块 Canvas 按窗口实际分辨率重新渲染，不再把 960×540 硬拉大

翻译层 `TR` 负责 UI 文本、物品名和长句规则，玩家输入的世界名和种子则保持原样。中文版不是把英文盖掉，而是把整个界面重新排了一次版。

## 部署

仓库叫 `terraria-deepseek-v4.1-flash`，托管在 GitHub Pages。项目页的路径固定包含仓库名，默认地址是 `https://stanl.top/terraria-deepseek-v4.1-flash/`，但我想要一个更干净的 `stanl.top/terraria`。

最后我在博客仓库的 `static` 目录里加了一个全屏入口，用它加载同域的游戏页面。这样地址栏可以保持为 `/terraria/`，存档也仍然在同一个 origin 下。它不是最优雅的路由方案，但足够简单，也不用再维护一份游戏副本。

上线后也要验收：打开 `/terraria`，再用 1920 宽窗口和手机尺寸各看一遍，确认入口不白屏、游戏能创建世界、键盘输入真的落在画布上。

## 现在的它

现在可以从两个地址进入：<https://stanl.top/terraria> 和 <https://stanl.top/terraria-deepseek-v4.1-flash/>。

它仍然只是一个单机游戏，只支持键盘和鼠标，没有手机触屏，也没有存档导入导出。内容也谈不上完整，离真正的泰拉瑞亚还很远。但它是可以玩完一轮的：建房子、探洞穴、挖矿、合成装备、打 Boss、看向导说话。

这次开发让我印象最深的不是又加了几个 Boss，而是那些很小的东西：鼠标有没有消失，中文字有没有压住血条，地址能不能记住。先做一个能跑的最小版本，再一遍一遍地玩它。
